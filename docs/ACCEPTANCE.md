# 验收标准

> 配套文档：`PRODUCT-PLAN.md`（做什么）、`AGENTS.md` 第 4 节（测试状态七级）。
> 本文解决的是另一个问题：**「我说通过了」凭什么可信。**

---

## 0. 一句话定义

> **验收不是「测试跑绿了」，是「另一个人拿着这份记录，能在自己机器上复现出同样的数字」。**

所以每一条验收都必须带三样东西：**命令、数字、判据**。缺任一样，只能报「未测试」。

---

## 1. 四把尺子

任何一次改动，同时过这四关才算完。**四把尺子不可互相替代**，这是本文最重要的规则。

| 尺子 | 判据 | 证据形态 | 谁判 | 替代关系 |
|---|---|---|---|---|
| **R1 机器可判** | 全部测试有数字且全绿 | 命令 + 输出 | 机器 | 不能替代 R2 |
| **R2 结构性可证** | 改动范围与声明一致 | `git diff --stat` + 逐行 diff | 机器 | 不能替代 R1 |
| **R3 真机可见** | 真浏览器、真站点、真产物 | URL + 条目数 + `ffprobe` 输出 | 我 | 不能替代 R4 |
| **R4 用户点头** | 用户明确确认 | 用户原话 | 你 | 无人可代 |

### 为什么 R1 不能替代 R2

R1 的断言是**我写的**。用实现去写断言，等于用答案出题。R2 是结构性证据，它不看行为，只看「有没有偷偷改别的」——这是唯一不依赖我判断的尺子。

在 S0 这一刀上，R2 就是：`background.js` 只 +4 行（3 注释 + 1 `importScripts`），`popup.js` / `inject-main.js` / `native-host/` **零改动**。旧路径没被碰过，所以「行为不变」不是承诺，是算得出来的。

### 为什么 R3 不能替代 R4

R3 我能自己跑，所以它仍然是「我说的」。只有你能说「这个结果是我想要的」，才算验收通过。这两档之间的差距，就是「能跑」和「能用」。

---

## 2. 每一刀必须有一条「不依赖断言的证据」

这是防 AI 自证失败的硬规则。断言全绿**不能**作为唯一证据，必须额外有一条：

| 证据类型 | 形态 | 适用 |
|---|---|---|
| **结构证据** | `git diff` 只出现在声明过的文件/行 | 纯增量、重构、加开关 |
| **真实数据证据** | 真机 dump 的真实输入喂给新函数，人工核对产出 | 新解析器、新模型 |
| **反向证据** | 故意改坏一处，测试**必须**红；不红说明断言是空的 | 所有新增测试 |
| **基线证据** | 改动前先跑一遍存成 json，改动后同页面重跑做字段级 diff | 声称「行为不变」 |

**「基线证据」是最容易被跳过的一条，也是最贵的一条。** 没有基线时，「行为零改动」只是声明；有基线时，它是可比对的数字。`tools/site_audit.mjs --out` 输出的 json 就是现成的基线格式。

---

## 3. 禁止用语

以下说法一律不算通过，遇到只能报「未测试」或「自动化测试通过（未真机）」：

- 「应该能过」「基本正常」「看起来没问题」「大概率没问题」
- 「静态检查通过」当成「测试通过」
- 「之前跑过」——每次改动后必须重跑
- 「逻辑上不可能出错」——d-010 的教训：函数压根没执行，盯了函数内容查三轮

允许的说法只有三种，且都必须带数字：

```
自动化测试通过（未真机）：JS 805 项 / Python 16/16 / node --check 全过
浏览器实测通过：<站点 URL> 抓到 N 条，产物 <文件> ffprobe 显示 <轨道>
验收通过：用户确认「<原话>」
```

## 4. 一票否决项

任何一条命中，本轮**直接不通过**，不讨论其他指标：

| # | 否决项 | 为什么是一票 |
|---|---|---|
| V1 | 页面 console 出现新异常/新警告 | 扩展不许污染宿主页面，这是产品底线，不是指标 |
| V2 | 下载产物 `ffprobe` 打不开，或时长偏差 >5% | 「下完了打不开」是本类产品的第一大翻车点 |
| V3 | 条目数比基线**少** | 漏抓比错抓隐蔽：用户以为自己找错了站 |
| V4 | `manifest.json` 版本号没升 | 装的人分不清新旧，回滚无从下手 |
| V5 | 新增网络/读体行为没有独立开关 | 隐私边界不能默认扩大 |
| V6 | 新增规则没有对应测试 | 规则会腐烂，没测试的规则三个月后没人敢删 |

## 5. S0 验收单（会话数据契约 · 1.3.43）

S0 的验收**分两步**，不是一步。这一点必须写清，否则以后会误以为 S0 全过了：

- **Step 1（本刀已做）**：模型存在，纯函数，行为零改动。
- **Step 2（未开始）**：把 `msBuildSession` 接进 `background.js` 的条目流，与旧 `items` **双跑并行**，逐页比对等价。

`PRODUCT-PLAN.md` L0 里写的「两条路径产出等价结果」指的是 **Step 2**。Step 1 能验的只有「不改坏」，不能验「等价」。

### Step 1 验收单

| # | 条目 | 判据 | 状态 | 证据 |
|---|---|---|---|---|
| S0-1 | 语法 | 全部 `extension/*.js` 过 `node --check` | ✅ | 全过 |
| S0-2 | JS 测试 | 全量数字且全绿 | ✅ | **805 项**（另 focus_scope / group_key 静默通过） |
| S0-3 | Python 测试 | 全量数字且全绿 | ✅ | **16 / 16** |
| S0-4 | **旧路径零改动**（R2） | `git diff 776334a` 里 `background.js` 仅 +4 行，`popup/inject/native-host` 零改动 | ✅ | 见第 1 节 |
| S0-5 | 真机 SW 内存活 | 扩展加载后，SW 内 `typeof MSSession === "object"` | ⬜ | — |

| S0-7 | 真实数据回放 | 真机 dump 的 `items` 喂 `msBuildSession`，人工核对 `tracks`/`variants`/`manifest` 是否合理 | ⬜ | — |

**当前档位：自动化测试通过（未真机）。** S0-5~8 做完才是「浏览器实测通过」。

## 6. S1 验收单（读媒体响应体 · 下一刀）

这一刀的验收第一次有**你能直接感知**的结果，所以判据要写死：

| # | 条目 | 判据 | 谁来判 |
|---|---|---|---|
| S1-1 | 出现清晰度 | 一个真实 m3u8 站，popup 出现 **≥2 档**变体，且档位名称来自清单本身（不是猜的） | 我 + 你 |
| S1-2 | 选中档位真实生效 | 选**非默认**档下载，`ffprobe` 实测宽高**等于**所选档，不是回落到最高/最低 | 我 |
| S1-3 | 页面不被读体搞坏 | 读体期间页面视频**播放不中断**（`resp.clone()` 生效），console 零新异常 | 我 |
| S1-4 | 关闭开关可回归 | 关掉「读响应体」后，与 1.3.43 基线**逐条一致** | 我 |
| S1-5 | 大清单不卡 | 500 分片的清单被正确截断到 ≤256KB，页面侧耗时 <50ms | 我 |
| S1-6 | 失败静默 | 断网/跨域读体失败时 `catch {}`，页面与列表行为不变 | 我 |

其中 **S1-2 是本刀唯一的硬指标**：只证明「显示了几档」不算成功，必须证明「选的哪档就下到哪档」。否则就是又一个「看起来有功能」。

## 7. 每条验收记录写进 DEVLOG 的模板

```
验收（<版本号>）
- R1 自动化：JS <n> 项 / Python <n>/<n> / node --check 全过
- R2 结构：git diff <base> --stat 中，<文件> 仅 <n> 行（<说明>）
- R3 真机：<站点> <URL>，条目 <n> 条（基线 <n>），产物 <文件> <n> 字节，
        ffprobe：<codec> <w>x<h> <duration>s
- 反向：改坏 <函数> → <测试文件> 第 <n> 项红（已还原）
- 档位：浏览器实测通过 / 自动化测试通过（未真机）
- 未做：<明确列出，不许留空>
```

最后一行「未做」是强制的。**验收报告的价值一半在于它承认了什么没验。**
